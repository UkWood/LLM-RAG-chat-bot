## Ограничения и качество источников

`docs/content-model.md` содержит исторический статус незавершённых работ, тогда как схема и шаблоны уже реализуют часть из них. Приоритет проверки: текущая схема + реальные записи + маршруты. Даже опубликованный сайт может содержать заготовки, устаревшие сведения и противоречия: публичность не равна технической достоверности.

Например, карточка `bkd-pk-rf-2.md` содержит обозначение «БКД-ПК-RF.2» со смешением алфавитов, Ethernet/RS-485/RS-232, структурированные параметры и несколько PDF-ссылок. Это хороший кандидат для проверки точного поиска, но разрешение на включение в PUBLIC и актуальность версии необходимо зафиксировать отдельно.

Исходники сайта, `Old_Site`, SQL/служебные материалы, scripts, inventory, migration и docs не поступают во внешнюю LLM. Их чтение для discovery не является разрешением на включение в KB. Из inventory можно взять кандидатов ссылок для проверки, но не автоматически разрешать их загрузку.

## Что пока не проверено

- Доступность и содержимое внешних PDF, права на конкретные версии и качество извлечения таблиц.
- Производительность локальных embeddings/reranker на целевом CPU, размер будущего корпуса.
- Актуальная модель, endpoint, регион, условия хранения данных и streaming Alibaba Model Studio: проверить по официальной документации перед интеграцией.
- Реальная сборка сайта: для discovery не требовалась и не выполнялась.
- Развёртывание на целевом сервере и реальный LLM-запрос.

## Правило дальнейшей работы

Все изменения AI — только в `UkWood/LLM-RAG-chat-bot`. Сайт используется как вход read-only; без коммитов, push, миграций и правок URL/assets. Снимки входных данных фиксируются commit/hash. Полную копию сайта не коммитить в AI-репозиторий.
