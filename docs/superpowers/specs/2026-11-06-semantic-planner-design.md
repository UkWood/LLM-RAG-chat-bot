## Goal and evidence

Improve supported-question coverage without making an unrelated canonical quote look like an answer. Corrected V2 remains available and V1 remains default. Its independent quality is NOT_RUN. The old first-blind experiment measures frozen7bc6f11 only:8/24 positives,14/16 refusal/clarification outcomes;14 positive misses were unsupported clauses and2 lacked selected evidence. These aggregate outcomes motivate this proposal; consumed questions/labels are not new calibration or evaluation data. Later custom review demonstrated that discarded negation, protocol qualifiers and modification intent can survive exact quote validation. Their regressions are permanent requirements.

This experiment adds a bounded proposal of typed predicates plus retrieval for each complete need. It does not implement general engineering reasoning, instructions, diagnosis, compatibility, numeric calculations, a generative planner, API/UI, cloud or real-source ingestion. No new dependencies/models/downloads/approvals. Same synthetic canonical snapshot and existing pinned E5/mmarco bundles; license declarations remain experimental provenance, not production clearance.

## Approaches

1. Extend deterministic grammar only. Transparent and cheap, but another broad context-word list repeats the demonstrated failure mode and does not establish paraphrase coverage. Keep explicit grammar for roles/operators and as the baseline, not as an ever-growing list of ignored words.
2. Selected direction: a role-aware bounded parser plus semantic predicate proposals using the existing local mmarco cross-encoder, with calibrated abstention and canonical all-needs validation. Uses existing CPU resources. Its retrieval logits are not probabilities or entailment; feasibility and safety on held-out questions remain unproven. Stop the experiment if calibration cannot produce useful coverage without incorrect answers.
3. A new constrained generative planner may handle broader language, but needs a separately chosen/licensed model, runtime/dependencies, resource budget and semantic validation. Outside this stage; do not download one as a fallback.

The user selected direction2; exact bounds, data protocol and acceptance below were explicitly approved.

## Role-aware question contract

Create an explicit V3 opt-in path, without fallback to V1/V2 after refusal. One captured IndexSet throughout planning, retrieval, projections, gate, provider and publication. Keep question<=4000characters, entities<=3, needs<=4, evidence<=5chunks/8000characters, one same-retrieved-manual anchor maximum. No corpus, ingestion-parser or canonical-projection-schema change in this stage.

Parse complete clauses into typed roles: lookup construction, predicate phrase, exact entity/type selector, source constraints, supported qualifier, conjunction. Retain original character spans and a role trace for all consumed content; no global list may silently discard substantive tokens. Allow grammatical punctuation explicitly; refuse unrecognized symbols/fragments instead of losing them during tokenization. Conjunction/source propagation must be explicit, including shared trailing scopes; ambiguous attachment clarifies rather than drops a constraint. A comparison means independent facts for each entity, not a computed difference or compatibility conclusion. Disjunction, negation, modification/how-to/possibility requests and unsupported mixed clauses refuse unless a narrowly declared lookup construction proves the existing software-purpose/configuration-interface meaning. Preserve the three review regression families from PR10.

Entity resolution and document-kind/representation binding are deterministic. Exact designation includes suffix and Cyrillic/Latin distinctions. One-edit ambiguity clarifies; unknown entities refuse. Neural scores may not select a nearest entity or invent a source/selector. No new target-specific implicit relationship selector is added. Keep only the existing unique-type Software lookup for generic software-purpose questions without an explicit target designation: it creates an ordinary purpose need for that Software and must quote its full canonical purpose statement. An explicit target designation plus an implicit related software/entity request is unsupported in this stage, because existing needs/projections cannot bind that target relation. Refuse it rather than infer the relation from metadata or silently drop the target. Type-reference lookups claim only the canonical type, not an engineering relationship. Existing explicit-subject composition/purpose/configuration-interface needs retain their span-supported contracts; no hidden extra relation obligation or uncharged need.

Continue rejecting explicit Modbus/TCP/RTU selectors until a separately specified typed protocol capability exists. Existing interface selectors, named-spec labels, document references and type references retain their exact contracts. Unrecognized source/table/number/unit qualifiers are never ignored. Schema predicates and source constraints remain those of V2; the router proposes a predicate, not a value or evidence sufficiency.

## Semantic predicate proposal

After deterministic structural parsing, score each unresolved predicate phrase against a versioned catalogue of neutral capability descriptions. Catalogue keys are (predicate, selector) with generic domain descriptions. Named-spec candidates use only exact labels from currently eligible captured canonical projections; a generic spec class without a bound label is not a complete need. No neural/free-text selector is permitted. No source values, expected answers, question IDs or dataset text. Do not ask the router to complete entity resolution, source scopes, negation, arithmetic, missing clauses or unknown qualifiers.

Use the existing Reranker.score_pairs(query, passages) interface and pinned mmarco artifact. At most4 phrases,20 catalogue candidates each:<=80 intent pairs. Reject catalogue overflow rather than hide labels. Validate finite score count, catalogue identity and model identity; ties abstain. Use a frozen absolute-score minimum and top1-minus-top2 margin, selected on calibration only from a predeclared finite grid. These numbers measure empirical separation, not confidence/truth. Check full pair token length with the verified tokenizer before inference; reject any phrase/catalogue entry that would truncate semantically relevant input. Do not rely on a character-to-token estimate or silently truncate the question.

A typed plan is accepted only when every clause has a permitted structural interpretation, every phrase has an accepted predicate proposal, all explicit roles/constraints have bindings and all budgets hold. Low/ambiguous scores clarify only when several supported interpretations remain; unsupported structure refuses. Infrastructure/model/tokenization failures are errors, not successful refusals. The router cannot approve a request denied by structural/policy guards, and cannot emit a partial plan to generation.

Important limitation: consuming a phrase span and selecting a high-scoring description does NOT prove its meaning. Unknown paraphrases or novel unsupported intentions may still be misclassified. The canonical evidence gate cannot detect every wrong question-to-predicate mapping. This is an experimentally evaluated risk, not a formal safety guarantee. Require separate plan/requirement accuracy and adversarial outcomes; V3 remains disabled by default even after a small-set pass.

Deterministically recognized complete lookup clauses may bypass intent scoring using the same role contract. Whether a clause used exact recognition or semantic proposal is recorded before evaluation; no post-result per-case fallback or mode selection. Catalogue/templates/recognizers/thresholds/topology are frozen together.

## Need-directed retrieval and bounded evidence selection

Reuse the captured search APIs and current policy. For each resolved need, generate a deterministic search representation from canonical entity designation, schema predicate/selector and explicit source constraints; no model-authored query, expected answer or source value. Retrieve up to10 candidates per need using existing hybrid lexical/dense search. Four lists contain<=40 items before deduplication. Merge by deterministic round-robin of need/rank into a canonical unique pool<=30, after current eligibility filtering. Preserve the per-need ranks and pool-cut reason; no hidden unlimited search.

Rerank this pool once with the original question, at most30 passage pairs. Together with routing:<=110 cross-encoder pairs/question and<=4 hybrid queries, existing batching/runtime contracts. Retrieval score truncation remains a ranking limitation, not proof of a need; no fact may rely on unparsed text or rank score. Report cold/warm CPU p50/p95, pair counts and refusals; no latency SLA is asserted before measurements.

Select a bounded evidence set using canonical complete-group coverage of the resolved needs, not only global relevance. Build valid group options from eligible projections whose value spans are in the retrieved pool. Each option retains source constraints, full group cardinality and exact chunks; do not union partial groups or ignore conflicting/malformed eligible facts. Choose an all-needs union<=5chunks/8000characters using the objective below; if no complete feasible union exists, refuse. Prefer fewer unique chunks, then higher minimum option relevance, then total reranker relevance, with canonical IDs as final deterministic tie-break. The builder may choose a dynamic-programming implementation for4needs/30candidates, with a hard cap of10,000 retained states and200,000 option transitions; exhaustion refuses as evidence_selection_budget, reported as a false refusal when appropriate, never as a complete partial answer. These bounds are frozen before blind use; avoid unbounded powerset search. Gold labels never enter this selection.

V3 introduces an explicit plan/selection/gate contract while keeping V1/V2 public contracts and behavior unchanged. QueryPlanV3 holds the existing EvidenceNeed tuple, question hash, planner/catalogue/gate-schema revisions and role bindings (original-character spans with enum roles; no persisted raw question text). Role parsing must retain an original-span map during normalization. No new free-text predicate or relationship selector is allowed.

EvidenceSelectionV3 pins one complete canonical group option per factual need, or one canonical metadata reference per reference need, plus ordered retrieved candidate IDs and separately charged anchors. Each option contains canonical group/projection IDs and the full required value-span chunk union. A group ID alone without all of its members is insufficient. Selection is advisory until evaluate_v3 independently rebuilds canonical projections and validates those EXACT options: entity/predicate/selector/constraints, full group membership, retrieved-pool membership, canonical spans, all eligible-source conflict/malformed/partial-group rules, canonical references, budgets and policy. It must not independently choose another set of projection/group bindings. Provider quotes and backend references derive from the verified pinned bindings only. Mutation/omission of a selected member or substitution of a different group must fail closed.

Reuse/refactor pure validation helpers where useful, but do not pass a V3 selection through evaluate_v2 and assume its independently chosen bindings are authoritative. New V3 gate/schema identity is frozen separately; V2's existing config revision and projection schema stay unchanged. Whole-group consistency includes all relevant current eligible sources, not just the selected group: selection cannot conceal a conflict or malformed relevant fact. Preserve current atomic local_index AND local_generate, canonical projection identity, every need, source constraints and evidence budgets. Manual references may add only the existing one canonical same-retrieved-document anchor, charged to the same budgets and marked separately. Coverage selection cannot expand into another source, approve unranked engineering facts or resolve contradictory sources by rank. Recheck current policy before/after provider and before output as today. Fake provider emits only complete exact canonical quotes; backend rebuilds references/citations. No changes to production/default paths.
